# RESCUE-GUI-LIFECYCLE-01 — физический Windows Scan/Run (synthetic only)

## Контрольная граница

Тест запускает **реальный** `chaptera-rescue.exe` из распакованного переносимого ZIP. Он не вызывает обработчики `egui` напрямую, а использует Win32 `SendInput` и проверяет действительное активное окно по `HWND` перед **каждым** системным событием. Если фокус перешёл в другое окно, событие не отправляется, и приёмка падает.

Тест создаёт собственный синтетический `.pub` (валидный CFB с двумя SID потоками), вводит исходную и выходную папки мышью/клавиатурой, нажимает `Scan / add folder` и `Run / resume`. Корректность ввода подтверждается **не через глобальный буфер обмена**, а по каноническому `summary.json` в точной выходной папке: проверяются версия схемы, `source_free`, одно ожидаемое значение SHA-256, `pending → done_partial`, число фактических попыток, `outcome=partial`, два физически подтверждённых SID-потока и неизменные исходные байты. `Ctrl+A` отправляется одним упорядоченным пакетом `SendInput` с отпусканием модификатора. После Scan и Run дополнительно проверяется освобождение настоящей kernel-блокировки очереди, а не только наличие JSON-файла.

**Это только hosted/native Windows GUI Scan/Run acceptance, не полная приёмка Rescue.** Код не доказывает Pause/Cancel, два активных worker, drag-and-drop, чистую Windows 10/11, работу с настоящим частным корпусом 1556 PUB или установщик.

## Ручной запуск на подготовленной Windows

Предпосылки: Windows x64 с интерактивным рабочим столом, PowerShell, Python 3.12+ **только для тестового драйвера**, checkout именно той ревизии `rar2`, от которой выполняется проверка, и **полностью распакованный** технический ZIP с `_internal`, `chaptera-rescue.exe`, `rescue-engine.exe`, `pub.exe`, `portable-build.json`.

Из корня checkout:

```powershell
python -m unittest tools.test_rescue_gui_pointer_windows -v
python -m tools.probe_rescue_gui_pointer_windows --portable-dir "C:\RescuePreview\extracted"
```

Пути к приватным данным подавать нельзя: тест сам создаёт и удаляет исключительно синтетический PUB во временном каталоге. Перед запуском ZIP проверяется по каждому хешу `portable-build.json`; отдельный установленный Python **в PATH дочернего GUI** скрывается. Python у тестового драйвера есть, поэтому это **не доказательство отсутствия Python на машине**.

**Не запускать параллельно с другой GUI-автоматизацией, вводом пользователя или RDP-переключениями.** `SendInput` — глобальный OS input, не направленный вызов к конкретному процессу. Если Rescue потеряет фокус, тест останавливается без перенаправления событий. Уровень привилегий драйвера и Rescue должен совпадать; elevation/UIPI нельзя обходить.

Успех — одна JSON-строка `chaptera.rescue-gui-pointer-scan.v1` без путей и исходных байтов. Любое исключение, отсутствие реального окна, отсутствие записи очереди, SHA mismatch, неполные SID, удержанная блокировка или потеря фокуса — FAIL. На реальной Windows x64 перед отправкой событий проверяются Win64 ABI (`sizeof(INPUT)==40`) и уровень доступа к оконному вводу. При аварийном старте сохраняется ограниченный и очищенный от основных путей stderr. `source_commit` берётся из проверенного манифеста ZIP, а не из названия файла. В receipt отдельно указано `python_hidden_from_gui_path=true`, но `python_absent_on_host=false`: это не тест отсутствия установленного Python на тестовом компьютере.

## Граница CI

Эта ветка содержит только реализацию и самопроверки теста. В коде определены 24 unit-теста, включая один Windows-only ABI-тест. Число тестов в исходнике **не означает**, что они были выполнены; из-за отсутствия checkout и Windows runner в текущем локальном окружении полный актуальный прогон ещё не подтверждён.
